# Isolated Quick Controls preview

Run from the checkout; no installation, shell restart, or user configuration edit is required:

```sh
python3 tools/preview-qml.py
python3 tools/preview-qml.py --height 360 --focus-restore --output /tmp/omapeek-short.png
python3 tools/preview-qml.py --monitor-width 1080 --monitor-height 1920 --output /tmp/omapeek-portrait.png
python3 tools/preview-qml.py --monitor-width 3440 --monitor-height 1440 --output /tmp/omapeek-ultrawide.png
python3 tools/preview-qml.py --accessibility-check --output /tmp/omapeek-accessibility.png
python3 tools/preview-qml.py --keyboard-check --output /tmp/omapeek-keyboard.png
python3 tools/preview-qml.py --keyboard-check --height 320 --output /tmp/omapeek-keyboard-short.png
python3 tools/preview-qml.py --runtime-check
python3 tools/preview-qml.py --lint
```

The default image is `docs/screenshots/omapeek-quick-controls.png`. It renders the actual `QuickControls.qml` and `ControlsViewport.qml`, inside the same native `BorderSurface` and theme tokens used by `KeyboardPanel`. Its status is a deterministic fixture, not evidence of real window control. The theme comes from the machine's current Omarchy theme, so pixel colors/fonts can vary across machines. Generated designs in `output/` are never loaded by the plugin.

Offscreen Qt with the software renderer captures a QML-owned item using `grabToImage`. It cannot instantiate native layer-shell `KeyboardPanel` (no PanelWindow backend); `--runtime-check` therefore loads the complete `OmaPeekWidget` and `OmaPeekPanel` hidden in an independent Wayland Quickshell process. It injects a temporary fixture-only helper: status returns sample JSON, every other action is a no-op. It cannot call hyprctl or read/write a real controller snapshot. That instance quits itself; the harness never kills other shell instances. No live float/restore operation is performed.

`--focus-restore` gives the actual Restore button Qt keyboard focus and checks that the shared viewport scrolls it entirely into view, failing if it does not. This exercises the same `Window.window.activeFocusItem` signal and scrolling used inside the popup. The dated live record below covers native popup placement and outside-click dismissal; complete keyboard traversal remains inconclusive.

`--keyboard-check` uses QtTest inside an offscreen Quickshell fixture, delivering keys only to that process's QQuickWindow. It checks all 13 controls in both Tab directions, action command routing with Return/Enter/Space, dropdown selection/Escape/reopening, automatic trigger focus return, and focus after simulated monitor readback. At 320px it also checks each forward-focused control is revealed. No helper or compositor input is used. This requires the QtTest QML module. It does not establish live layer-shell focus, physical shortcut delivery, actual monitor movement, or hotplug behavior. See the 2026-10-05 release-confidence entry in [VERIFICATION.md](../VERIFICATION.md) for real neutral-window stacking evidence and the remaining owner checks.

`--lint` sets up temporary `qs.Ui`/`qs.Commons` import roots pointing read-only at `/usr/share/omarchy/shell`. qmllint currently reports dynamic QObject theme/bar properties and Quickshell's missing `QProcess::ExitStatus` type metadata; these are static metadata warnings, not syntax/import failures. Runtime fixture rendering and hidden full-widget loading complement lint. Do not describe lint as warning-free.

Current offline validation: 58 Python controller tests, plugin validation, Python compilation, QML lint, offscreen default/short/portrait/ultrawide captures, Restore focus reveal, and hidden complete-widget loading with the fixture helper. Controller dispatches in unit tests are mocked. The dated live records provide compositor/browser restoration evidence within their stated scope; complete physical hotplug acceptance remains pending.

Hotplug recovery handles tracked visible floats that have no assigned monitor or no screen overlap, including with Above off. Accessible manual positions with a valid monitor are preserved. Monitor add/remove events request maintenance through the 200ms timer; otherwise the 12-second fallback covers missed layout changes. Recovery attaches orphaned windows before changing pinning, uses silent workspace/monitor moves, and journals partial work without replacing the original restore snapshot. Hidden Show rejects saved geometry that is unreachable after output layout changes. With fresh widget code confirmed through IPC, physical DP removal recovered the same video onto HDMI automatically in about 0.3 seconds with Above off; the owner confirmed visibility, and focus/original restore state were preserved. Restore with DP absent, physical shortcut activation, and hidden unplug/Show with Follow off also passed with owner confirmation and controller readback. An earlier repeat had failed with cached old widget code, requiring a shell restart. The orphan-on-reconnect path has unit coverage and remains unverified against the final implementation. See the dated [physical test record](../VERIFICATION.md); no crash fix is established.

Keep-above uses `hl.dsp.window.alter_zorder({window="address:…", mode="top"})`, after checking PID and stable ID inside the same compositor eval. Closed/reused identities fail before dispatch; failed dispatcher results become errors. There is no legacy active-window fallback or focus dispatcher. The widget maintains this after relevant compositor events, with a 12-second fallback. See [Hyprland dispatchers](https://wiki.hypr.land/Configuring/Basics/Dispatchers/). Follow-workspaces uses pinning independently. Hide uses `special:omapeek-hidden`; avoid using that workspace for unrelated windows. If the original monitor disappears, restoration returns window modes/workspace on an available display rather than applying obsolete original geometry.

Review regression checks cover selecting a display while hidden with Follow off and showing on that display/workspace with correct geometry; a real file lock released by a short background thread for both shortcut toggle and Hide; bounded lock timeout and nonblocking/skippable maintenance; and Lua execution of the production raise script against closed, reused, hidden, valid, and failed-result compositor stubs. Lua tests require `/usr/bin/lua`; no real compositor mutation is used.

`--accessibility-check` runs `tests/AccessibilityChecks.js` against real rendered controls. It asserts button/radio/switch roles, labels, checked/selected states, the ComboBox role/name/current value on the actual focused dropdown trigger, accessible activation and option selection, and disabled actions emitting no commands. It also verifies controller readback still changes display/corner labels after selection, and direct option clicks choose the clicked row without hover. The dropdown is a local adaptation of Omarchy's native component because its private trigger/options need accessibility metadata. Buttons and toggles extend native controls. These are Qt accessibility metadata/action checks, not an end-to-end screen-reader audit.

User commands wait for the controller lock for up to three seconds, polling every 25 ms. Maintenance never waits and is suppressed while a widget user command is running. Hidden snapshots store intended monitor/workspace together; configuring a hidden display keeps the float hidden and Show uses that destination before computing geometry.
